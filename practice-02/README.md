## 4. Модель данных и функции

### Поля задачи, правила валидации и назначение файлов

Задача содержит следующие поля:

- `id` — положительное безопасное целое число, уникальное среди задач.
- `title` — строка длиной от 1 до 100 символов после удаления пробелов в начале и конце.
- `completed` — логическое значение (`true` или `false`), показывающее состояние задачи.
- `priority` — приоритет задачи: `"low"`, `"medium"` или `"high"`.

Основные правила валидации: `id` должен быть положительным безопасным целым числом, `title` — непустой строкой длиной не более 100 символов, а `priority` должен иметь одно из разрешённых значений.

Файл `task-service.js` содержит функции для создания, поиска, изменения, удаления и анализа задач. Файл `data.js` содержит исходные данные задач. Файл `main.js` используется для запуска и демонстрации работы программы. Файл `checks.js` содержит проверки корректности реализации.

### Результаты операций

При успешном выполнении операции возвращается объект с `ok: true` и соответствующими данными. Например, при создании задачи возвращается `{ ok: true, task: ... }`.

При ошибке возвращается объект с `ok: false` и описанием причины в поле `error`. Предусмотренные ошибки не должны обрабатываться через `throw`.

### Почему id не равен индексу

`id` и индекс массива имеют разное назначение. Индекс показывает положение задачи в конкретном массиве и может измениться после добавления или удаления элементов. `id` является постоянным идентификатором самой задачи и не зависит от её положения в массиве. Поэтому задачу можно надёжно находить по `id`, даже если порядок задач изменился.

### Почему getTaskStats возвращает число, а не строку с процентом

`getTaskStats` возвращает `progress` как число, чтобы результат можно было использовать в дальнейших вычислениях и сравнениях без дополнительного преобразования строки. Форматирование значения в процентную строку, например `"75%"`, относится к отображению, а не к вычислению данных.

### Какие объекты копируются при изменении задачи

При изменении задачи создаётся новый объект задачи, а исходный объект не изменяется. Также создаётся новый массив с обновлёнными задачами. Это позволяет не изменять исходное состояние напрямую и сохранять неизменяемость данных.

## 9. Вывод

По сравнению с ПР1 в ПР2 была реализована работа с задачами с использованием отдельных функций в `src/task-service.js`. Реализованы создание, поиск, фильтрация, получение названий, расчёт статистики, добавление, изменение статуса, переименование и удаление задач.

Возвращаемые значения используются для передачи результата операции в виде объекта с полем `ok`. При успешной операции дополнительно возвращается созданная задача или новый массив задач, а при ошибке — сообщение в поле `error`. Неизменность входных данных проверена в `checks.js`: операции создания, добавления, изменения и удаления возвращают новые результаты, не изменяя исходные массивы и объекты.
